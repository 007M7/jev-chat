# iOS 真机验 Vision OCR：具体操作

目的：**在真机上量出苹果自己的 Vision OCR 读微信中文聊天的准确率**。这个数字决定 Tier 1（本地离线识别）能不能承担主力、把云端视觉模型的调用量压到最低。只能在你自己的手机上做——我这边没有 iPhone。

预计耗时 15 分钟。不需要 Mac、不需要开发者账号、不需要装任何 App。

---

## 一、建一个快捷指令（5 分钟）

打开「快捷指令」App → 右上角 **+** → 改名 `Jev OCR 测试`。加三步动作：

**第 1 步 · 取图**
- 搜 **截屏**（Take Screenshot）→ 添加
- 再加一个 **从图像中提取文本**（Extract Text from Image）→ 输入接上一步的截屏
  - 中文版可能叫「从图像中提取文本」；搜「文本」或「提取」都能找到
  - 如果找不到它，说明系统版本不支持这个动作，告诉我，我换成"先存相册再读"的写法

**第 2 步 · 显示结果**
- 加 **显示结果**（Show Result）→ 输入选上一步的「文本」

**第 3 步 · 绑定触发（关键，否则每次要手动开 App）**
- 设置 → 辅助功能 → 触控 → **轻点背面** → 轻点两下 → 选 `Jev OCR 测试`

> 建议先把「从图像中提取文本」的**语言**检查一下：点开这个动作（如果有语言选项）确认包含中文。新版系统一般自动识别，不用设。

## 二、跑 5 类截图（5 分钟）

从微信里依次做这 5 种，每种**轻点手机背面两下**触发，然后把结果**截图存下来**或记下来：

| # | 场景 | 为什么必须测这一类 |
|---|---|---|
| 1 | 一对一，浅色主题，有来有回的文字 | 最基本场景，主力用例 |
| 2 | 一对一，**深色主题** | 气泡底色变了，颜色类判定全失效 |
| 3 | 群聊（有多个发言人昵称） | 昵称会不会被当成消息？ |
| 4 | 含**表情包/图片**的消息 | 本地 OCR 结构上读不到，用来确认这一点 |
| 5 | 一条**很长的折行消息** | 折行会不会被拆成多条 |

## 三、把结果给我（3 分钟）

两个办法，任选：
- 把 5 张截图直接发在这个对话里（像你之前那样）
- 或者告诉我"跑完了"，我用同一批图在 PC 上跑云端视觉模型做对照

## 四、我会给你什么

一份可比的对照表，按这四项逐图打分：

| 指标 | 为什么关心 |
|---|---|
| 中文识别准确率 | 决定 Tier 1 是否可用 |
| 消息条数是否与人工核对一致 | 折行合并/昵称污染会不会出错 |
| 表情包/图片是否被读到 | 预期本地 OCR 全部读不到（这决定 Tier 2 的触发频率） |
| 能否区分不同发言人 | 群聊场景的硬要求 |

对照的另一侧是 `deepseek-flash` 视觉模型在同一批图上的表现（已有实测：桌面深色群聊 7 条消息全对、贴纸和 emoji 都读出来了、昵称正确忽略）。

**结论怎么用**：
- 如果 Vision 中文准确率够高 → Tier 1 承担纯文字聊天，云端只在"有表情包/图片"或"本地置信度低"时调用，成本压到最低
- 如果 Vision 在聊天气泡上不准 → Tier 1 降级为"变化检测器"（只判断屏幕有没有变），每次都走云端，成本仍可控（一次分析约 4000 token 量级）

---

## 附：为什么不用别的方式验

- **不用第三方 OCR App**：验的必须是 iOS 系统自带的 Vision 引擎（App 里将来调的就是它），第三方 App 用的是另一套模型，数字不可迁移
- **不用电脑上模拟**：Vision 只在苹果设备上跑；PC 上的 easyocr 我已实测，与 Vision 无关
- **不走自建 App**：那需要先做 Phase 1 的云构建 + 自签，而这 15 分钟就能回答"值不值得做 Phase 1 的 Tier 1"
